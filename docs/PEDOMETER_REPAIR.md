# Шагомер Android — D059

2026-10-02: пользователь повторно сообщает, что Huawei Health считает без часов, FitEasy не считает. Это не доказывает доступность публичного TYPE_STEP_COUNTER для FitEasy; без модели/версии/журнала точная причина не установлена. Официальные API: https://developer.android.com/develop/sensors-and-location/sensors/sensors_motion и https://developer.android.com/about/versions/14/changes/fgs-types-required.

Исправления: запуск явно выбирает источник этого телефона; Auto пробует counter → detector → accelerometer, при неудачной пакетной регистрации повторяет без batching. Ручной выбор Auto/Counter/Detector/Software позволяет обойти датчик, который зарегистрировался, но молчит. После 20 с без валидных событий показывать предупреждение и предложение другого режима, не объявлять «работает» до первого валидного события. Отказ разрешения/старта/регистрации/записи виден в статусе и журнале.

Software — независимый приблизительный подсчёт по акселерометру 25 Hz: модуль ускорения, отделение гравитации, сглаживание, гистерезис и подтверждение серии ритмичных пиков; одиночные толчки и неверные данные не засчитывать. Это не алгоритм Huawei Health и не обещание одинакового числа шагов. Не использовать облако/Google/HMS и не требовать часы. Записывать накопленные события пачками не чаще двух секунд, не журналировать каждый sample/шаг.

Предпочитать wake-up датчик. Для software с обычным акселерометром нужна ограниченная partial wake lock, пока пользователь включил режим; timeout и редкое продление, освобождение при стопе/ошибке/разрушении службы. Это может расходовать больше батареи, чем аппаратный датчик. Не менять системные настройки энергосбережения автоматически.

Диагностика по кнопке: версия приложения/Android, модель, разрешение активности/уведомлений, доступные counter/detector/accelerometer, режим, последний технический статус, ограничения батареи. Без содержимого дневника, идентификаторов записей/устройства, ключей и чисел шагов. Копирование по действию пользователя; существующий журнал по-прежнему доступен в Справке.

Смена backend сохраняет сегодняшний итог и сбрасывает только baseline счётчика. Одновременно считается один backend, callbacks старого датчика после переключения игнорируются. Tombstones не воскрешаются. Shared source остаётся phone:<deviceId>, Windows получает записи LAN/backup и не запускает датчики. Режим/диагностика/wake lock локальные, схемы/LAN/backup не меняются; Linux остаётся просмотром импортированных шагов.

Проверки: синтетические неподвижность/поворот/одиночный толчок/ритмичная ходьба/NaN/таймстемпы и переключение baseline/дневной итог. Компиляция и пять пакетов. Реальная ходьба/карман/экран выключен/батарея Huawei требуют телефона; без него не отмечать исправление конкретного устройства проверенным.

# 0.4.6/26 — D080

Аппаратные counter/detector: пакетная задержка 60 с; при включённом экране flush каждые 5 с. Software: FIFO-пачки акселерометра 1 с при наличии очереди от 50 событий; после 3 минут без шагов акселерометр и wake lock снимаются до TYPE_SIGNIFICANT_MOTION или включения экрана (журнал: steps.software.parked / steps.software.resumed). Запись: 2 с при включённом экране, 0,5 с (аппаратная пачка) или 30 с (software) при выключенном; смена состояния экрана записывает накопленное сразу. Проверить на телефоне: ходьба с выключенным экраном в каждом режиме, возобновление software после покоя, смена суток.
