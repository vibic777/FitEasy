# Производительность и надёжность — 2026-10-02

vibic777. Решение D-052, 0.3.1/8. Проверка Android и Windows без изменения пользовательских данных.

## Наблюдения и изменения

- Стек работающего Windows FitEasy: AWT EventQueue ожидал события, взаимной блокировки на этом снимке нет. Один снимок не доказывает отсутствие задержек при движении мыши. JFR текущего установленного runtime недоступен: отсутствует jdk.jfr. Добавить модуль диагностики в последующие Windows runtime, без автоматической записи профилей.
- Перенести начальное чтение снимка/каталога в IO; кешировать производные UI-вычисления, фильтр каталога, палитру и переводы/подсказки. Это уменьшает повторную работу при таймерах и взаимодействии, не является доказанным диагнозом драйвера/GPU.
- Android кешировать только успешно зафиксированный неизменяемый Snapshot. Общая блокировка UI/шагомера сохраняется. Пропуск неизменённого снимка не пишет SQLite и не сообщает изменение. Recovery/очистка инвалидируют кеш; проверка конвертации читает реальную БД напрямую. Не держать открытые соединения/ключи в новом кеше.
- Свести пачку накопительных показаний датчика к последнему значению с отложенным сохранением до 100 мс; аппаратное batching до 5 секунд сохранено. Выбрано короткое программное окно вместо первоначально предложенных 5 секунд, чтобы уменьшить несохранённый хвост при выключении. Первое значение сразу фиксирует исходную точку, повторные значения не записываются. При разрушении сервиса — попытка сброса; после явного отключения/reset выключенный флаг запрещает повторное добавление данных. Ключ device-id расшифровывается один раз на сервис. Без wake lock/таймера в простое. При явном выключении возможна потеря ещё не записанного программного хвоста до 100 мс; при аварии следующая накопительная запись обычно восстанавливает разницу, но доставка датчиком/ОС не гарантируется. Перед сменой суток/boot/count сбрасывается предыдущая пачка; разница на границе суток сохраняется как неоднозначная.
- Коллектор UI и опрос напоминаний работают только при foreground; при возврате загружается актуальный снимок. Опрос — IO. Ручной таймер прогулки использует монотонное время и обновляет экран только в foreground; тренировка сохраняет прежнее правило паузы.

## Проверки и границы

Проверить чистые функции датчика (пачки, день/перезапуск, повтор, инвалидные значения), подтверждение кеша после успешного commit/отказа/no-op, прежние тесты/компиляцию/пять сборок. Профили и синтетические данные находятся только в ignored build/. Проверки не запускают reset пользовательской базы.

Фактические результаты записать в ИСПРАВЛЕНИЯ.md. Нельзя утверждать измеренное ускорение мыши, FPS или снижение расхода батареи без одинаковой нагрузки на устройстве. Нормализация JSON-хранилища, перенос всех пользовательских операций записи/шифрования/экспорта из UI и реальные длительные тесты батареи остаются отдельными работами. Форматы SharedData/LAN/Backup не меняются. Ползунки сохраняются после завершения движения.

# 0.4.31/51 — D115, 2026-10-08: напоминания, будильник, уведомления

Проверен путь «будильник сработал → уведомление показано → следующий будильник поставлен» на Android и таймеры Windows. Что найдено и что сделано:

| Где | Что было | Что стало |
| --- | --- | --- |
| Android, чтение настроек напоминаний | Каждое чтение списка напоминаний, состояний, языка и переключателей заново обращалось к хранилищу ключей и расшифровывало значение: около тринадцати обращений на одно срабатывание и одно на каждое сохранение любой записи дневника | Запечатанное значение открывается один раз на процесс (OpenedTexts), список и состояния разбираются один раз на изменение; ключ ищется один раз |
| Android, изменение одного напоминания | Будильники всех напоминаний ставились заново, на каждое — запись в журнал | Переставляется только изменённое; в журнале одна строка |
| Android, смена часов или пояса | У всех напоминаний снимались будильники и уведомления, ждущие ответа показывались снова | Только заново ставятся будильники; повторный показ остался для перезагрузки и обновления приложения |
| Android, сводка в шторке | Канал и намерение готовились до сравнения текста; ближайшее время бралось дважды | Сначала сравнение; ближайшее время считается один раз на напоминание |
| Android, своя мелодия | Приложение просыпалось каждые 250 мс всю минуту звучания (до 240 раз) | Только пока громкость нарастает, затем один раз — чтобы закончить; без нарастания — один таймер |
| Windows, мелодия | Таймер каждые 250 мс всю минуту | То же правило, что на Android |
| Windows, таймеры напоминаний | После сна компьютера таймер опаздывал на время сна | Раз в минуту сверяются часы; после скачка таймеры ставятся заново |

Надёжность: будильники, потерянные при принудительной остановке приложения, возвращаются при его открытии; конец звучания мелодии не зависит от засыпания процессора (блокировка сна только на время звучания, не дольше минуты); экран будильника при втором напоминании показывает его, а не первое.

Оставлено как есть, с причиной: точные будильники (каждый — отдельное пробуждение) нужны, чтобы напоминание приходило в свою минуту; режим экономии батареи уже разрешает системе объединять пробуждения. Экран будильника включает дисплей — это его назначение, он выключен по умолчанию. Запись базы в потоке интерфейса остаётся следующей ступенью (D102).

Расход батареи в ватт-часах, число пробуждений и поведение на телефоне не измерялись: изменения Android проверены только сборкой.
