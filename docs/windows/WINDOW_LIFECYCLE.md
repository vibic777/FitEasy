# Окно и установка Windows — 2026-10-02

D072: меню правого клика трея открывает нужный раздел восстановленного окна. Переход при блокировке ждёт входа; последняя команда применяется один раз после разблокировки. Несохранённая заметка требует подтверждения перехода. Напоминания ведут к общему управлению и статусам, действия защищены входом в приложение. Язык меню следует языку приложения, обновление событийное. Двойной клик сохраняет обычное открытие; при отсутствии SystemTray приложение работает без меню.

0.3.9/16: новое удаление MSI/EXE спрашивает удаление данных на 10 языках, default Нет. AskDeleteData после InstallValidate и до InstallInitialize, включая basic UI; /qn без вопроса сохраняет данные. Явное FITEASYDELETEDATA=1 позволяет очистку. DeleteData после успешного InstallFinalize, условие REMOVE="ALL" AND NOT UPGRADINGPRODUCTCODE. Только текущий LOCALAPPDATA/FitEasy; exact target, reparse и занятые файлы проверяются до очистки. Не затрагивает backup вне папки, portable, fiteasy.home override или другие профили. При ошибке возвращается ошибка деинсталляции/запись MSI журнала; успешное стирание не объявляется. До очистки интерактивно предлагается закрыть приложение штатным IPC/вручную. Для silent пользователь должен закрыть приложение заранее. Новый вопрос действует после установки этой версии; старый cached MSI изменить новым APK/EXE невозможно. Условия/порядок/область проверены без реальной деинсталляции.

Начиная с 0.2.3/5 managed MSI локализуется после создания базового jpackage пакета. EXE содержит этот окончательный MSI и открывает тот же мастер; десять языков определяются по UI-языку Windows, иначе английский. Проверку запущенной программы выполняет локализованная .NET custom action вместо PowerShell; принцип зарегистрированных путей/штатного IPC-выхода сохранён. Галочка запуска переводится, checked по умолчанию, действует только при полном интерактивном UI. Подробности и параметры unattended: INSTALLER_LANGUAGES.md. Старые сведения о PowerShell ниже относятся к исходной упаковке до 0.2.3.

Portable ZIP: отдельная папка data рядом с приложением; блокировка экземпляра/IPC/трей работают для неё. Установщик не закрывает portable копию по одному имени процесса: проверка основана на зарегистрированном пути установленной версии. Runtime входит в архив.

vibic777 запросил галочку «Сворачивать в трей при закрытии», защиту от двух экземпляров, проверку запущенного приложения при установке с выбором автоматического/ручного закрытия. Notio-Windows SingleInstance.kt и installer/close-running.ps1 изучены как референс.

Настройка закрытия индивидуальна для устройства, по умолчанию включена. При отсутствии трея закрытие завершает процесс. Полный выход останавливает таймеры/файловые задачи; фоновые напоминания требуют работающего процесса. Второй экземпляр с той же папкой данных должен поднять первое окно и выйти до открытия БД. Блокировка файла освобождается ОС после аварии. Команда активации/выхода по loopback требует случайного локального токена; токен исключён из Git и никогда не передаётся LAN.

Установщик до замены файлов предлагает штатный выход либо ожидание ручного закрытия/отмену установки. Принудительного завершения нет. Проверяются полные пути из Windows uninstall registry для FitEasy/vibic777. Managed jpackage задачи добавляют свои WiX hooks к стандартному шаблону JDK в build/: packageManagedMsi/packageManagedExe. Обычные packageMsi/packageExe оставлены стандартными, для выдачи использовать managed. Диалог запускается в интерактивной UI sequence до ExecuteAction; silent режим использует стандартный MSI/Restart Manager. Реальную установку/обновление ещё нужно проверить. При несохранённой заметке штатный выход предупреждает; старые версии без IPC требуют ручного завершения.

D082 / 0.4.8/28: шапка приложения служит заголовком окна Windows (JetBrains Runtime CustomTitleBar, как в Notio-Windows); системные кнопки поверх, цвет по теме. Только Windows; общий код читает LocalWindowBar, Android/Linux без изменений.

D102/D104 (0.4.21/41): режим отрисовки по умолчанию «Автоматически» — свойство skiko.renderApi не задаётся, библиотека выбирает Direct3D и сама откатывается; файл renderer-mode.txt с ручным выбором действует как раньше. Меню трея получает пункт «Заглушить напоминание» на время звучания мелодии.

D112 / 0.4.28/48: один движок синхронизации на время работы приложения (SyncHost); переключатель «Постоянно ждать синхронизацию» — секрет устройства sync-always, по умолчанию выключен. Windows принимает синхронизацию, пока приложение запущено, включая трей; Android — пока приложение на экране, без фоновой службы. Протокол LAN 7 и форматы прежние.

D115 / 0.4.31/51: проверка кода напоминаний на расход батареи и надёжность. Android: значения, запечатанные ключом устройства, открываются один раз на процесс; будильник переставляется только у изменённого напоминания; смена часов не снимает уведомления; при открытии приложения будильники ставятся заново; звук своей мелодии будит приложение только на время нарастания громкости; экран будильника показывает последнее сработавшее напоминание. Windows: после сна компьютера или смены часов таймеры ставятся заново, пропущенное не более получаса назад показывается один раз; таймер мелодии тот же, что на Android. Данные, SQL 2, LAN 7, Transfer 5, backup 5 не менялись. Новое разрешение Android WAKE_LOCK — только на время звучания мелодии.
