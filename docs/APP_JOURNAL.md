# Журнал приложения и шагомер — D-055

Новый запрос: экспорт из журнала в JSON/TXT/LOG. UTF-8, локальный системный выбор файла; TXT/LOG сохраняют исходные строки, JSON содержит version 1/appVersion/build/generatedAt и entries timestamp/level/event/stack. Неполные строки не теряются: raw. Экспорт не включает options.json, SMTP/ключи/дневник, не добавляет числа шагов; чтение/кодирование вне UI. Общая реализация Android/Windows, Linux позже.

2026-10-02, vibic777. Изучены Notio-Android core/common/AppLog.kt, CrashLog.kt и SettingsScreen.kt (AppLogOptions/AppLogDialog), Notio-Windows shared/AppLog.kt: уровни, отдельный writer, ротация, очистка ежедневно по умолчанию, просмотр/копирование, FATAL независимо от выключенного обычного журнала. Реализация FitEasy самостоятельная; код/ресурсы не копируются.

Оба клиента: журнал в Справке и разделе справки настроек. Включение, уровни DEBUG/INFO/WARN/ERROR/CRITICAL; FATAL всегда. Срок хранения 1–8760 часов, по умолчанию 24. Автоочистка никогда/день/неделя/30 дней (день по умолчанию): при поступлении записи, без фонового будильника, удалить строки старше выбранного срока. «Никогда» отключает возрастную очистку, ротация остаётся: два файла по 512 KiB ограничивают рост. Очистить вручную, обновить, скопировать журнал в буфер обмена. Журнал локальный, не входит в LAN/backup; наружу автоматически не отправляется.

Покрытие через общие границы: startup/shutdown/foreground, UI-навигация/сохранение/ошибки, загрузка/транзакции БД/восстановление/шифрование, операции файлов/backup/restore/export, LAN connect/send/receive/errors, планировщик/доставка/управление напоминаниями, запуск/разрешение/наличие датчика/регистрация/первое показание/остановка/ошибки шагомера. Не журналировать каждый кадр/шаг/движение мыши. Сообщения фиксированные технические event ID, без значений дневника, UUID записей, чисел шагов, файловых путей, паролей/кодовых слов/SMTP/ключей. Ошибки содержат класс и безопасный стек (без Throwable.message).

Java/Kotlin необработанная ошибка синхронно записывается перед вызовом прежнего crash handler. Android Application устанавливает обработчик до Activity/Service/Receiver; Android 11+ на следующем запуске журналирует собственные process exit reasons (native crash/ANR/low-memory/остановка). Native crash Windows, kill процесса, выключение питания, исчерпание диска не могут гарантировать выполнение Java-handler; не утверждать обратное. Очередь обычного writer ограничена, журнал не должен блокировать UI или ломать приложение при собственном отказе.

Windows не измеряет телефонные шаги: скрыть запуск/остановку/источник «Этот телефон», оставить ручной ввод и просмотр источников Android/LAN/backup. Android: диагностировать permission/датчик/службу, fallback TYPE_STEP_DETECTOR при отсутствии TYPE_STEP_COUNTER. Первый накопительный счётчик — baseline, не ранее пройденные шаги; detector считает только новые события. Нельзя доказать работу конкретного телефона без него; журнал позволяет получить точную точку отказа.
